## 二、你反馈的「预约通知点开启没反应」

### 根因（三层叠加）

**① 一个"看起来在兜底、实际必然失败"的降级逻辑（主因）**

`utils/subscribe.ts` 里原本写着：批量请求失败 → 自动只重试第一张模板。

但微信规定 `wx.requestSubscribeMessage` **必须由用户点击手势同步唤起**，而这段重试发生在 `await` 之后 —— 手势早已用掉，
第二次调用**必定**返回 `fail can only be invoked by user TAP gesture`。

更糟的是：这条错误是**开发者层面的提示**，它会**覆盖掉真正的失败原因**（模板 ID 无效 / 用户永久拒绝 / 总开关关闭），
于是你在真机上只会看到一句莫名其妙的英文报错，完全查不出问题。

> 已移除该降级，改为**如实上报失败原因**。

**② 批量请求的"全有或全无"**

微信一次最多带 3 张模板，但**只要其中任意一张无效（未选用 / 不属于本账号 / 已过期 / 已封禁），整批被拒，一张卡都弹不出来**。
所以你点上"开启"可能表现为"什么都没发生"。

> 已新增「只开『预约成功通知』这一张」入口：用一次全新点击手势单独授权最关键的那张，成功率最高。

**③ 看不到自己处在什么状态**

两种情况微信都不会再弹卡，但用户完全看不出来：
- 你此前在授权卡上勾过「**总是保持以上选择**」并拒绝 → 微信永久记住拒绝；
- 你关闭了「接收订阅消息」总开关。

> 已接入 `wx.getSetting({ withSubscriptions: true })`，**弹层里直接显示**：
> 总开关状态 + 4 张模板各自在微信侧是「已允许 / 已拒绝（不再弹卡）/ 已封禁 / 未记录」，
> 并给出唯一正确的下一步（去设置页 / 重新授权）。

### 顺带修掉的一个真实隐患

前端与云端各存了一份「模板 ID + 关键词编号 + 20 字截断规则」：
- 前端走的是旧路径（传 `templateId` + 自己拼 data）→ **云端的 20 字截断根本不生效**；
- 两边不一致时会出现「授权用 A 模板、发送用 B 模板」→ 用户永远收不到。

> 已让**云端成为唯一发送源**：前端只传 `type` + 内容，模板查表、关键词拼装、截断、时间格式化全部收敛到 `cloudfunctions/notify`。
> 时间格式化也统一为**北京时间**（此前前端按运行环境本地时区格式化，跨时区会显示错的开场时间）。

## 三、体检发现并已修复的缺陷

| # | 级别 | 问题 | 影响 | 修复 |
|---|---|---|---|---|
| 1 | **P0** | `adminStats` 鉴权**只认环境变量** `ADMIN_OPENID_HASHES`，而 `adminOps` / `adminSeatMaintain` 都支持 `users.role === 'admin'` 回退 | 靠 role 提权的管理员，管理页能改座位、能看预约，**一进「统计」就报 ADMIN_NOT_CONFIGURED** —— 同一个后台两套权限判定 | 与另两个云函数对齐，鉴权改 async 并支持 role 回退 |
| 2 | **P1** | 订阅授权存在「批量失败→自动重试」的**无效降级**，且失败原因被开发者提示覆盖 | 「点开启没反应」，且完全查不出原因 | 移除无效降级；新增单张授权入口 + 微信侧状态诊断（见 §二） |
| 3 | **P1** | 订阅模板/关键词/截断规则**前后端各一份**，且前端旧路径绕过云端截断 | 两边不一致则永久收不到通知；20 字截断失效 | 发送侧收敛到云端，前端只传 `type` + 内容 |
| 4 | **P2** | 座位占用拦截错误码不统一（`adminOps` 返回 `SEAT_BUSY`，`adminSeatMaintain` 返回 `SEAT_OCCUPIED`） | 管理页只对 `SEAT_OCCUPIED` 给友好提示 → 走另一路径时用户只看到笼统的「修改失败」 | 统一为 `SEAT_OCCUPIED` |
| 5 | **P2** | `floor` 类型不一致（云端写 `String`、前端声明 `number`、seed 是数字） | 类型承诺与实际数据不符 | 三处统一为**字符串**（含 `category.ts` 读入时的兼容转换） |
| 6 | **P2** | `RoomQuery` 声明了 `date` / `features`，但 `roomList` 白名单从未接受它们 | `validateEvent` **静默剥离**：调用方以为筛过了，实际拿到全量数据（当前调用方未传，属埋雷） | 清理声明并注明"按属性筛选请在前端做" |
| 7 | **P2** | `roomList` 返回 `occupiedCount`，前端类型未声明、无人读取 | 白算一个字段，房间卡片无法显示"已占用 N" | 在 `RoomSummary` 中如实声明 |

> 另有 1 处连带修复：统一 `floor` 为字符串后，`services/category.ts` 的对应类型错误一并处理（TS 恢复 0 错）。

- `services/recommendation.ts` 的 `recommendSeats()` 全项目 **0 调用**（只在定义处出现）；
