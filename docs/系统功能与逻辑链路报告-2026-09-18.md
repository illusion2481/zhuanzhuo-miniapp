# 专注座 · 系统功能与逻辑链路报告

> 生成时间：2026-09-18
> 范围：`miniprogram/`（前端）+ `cloudfunctions/`（云函数）+ `docs/`（文档）
> 说明：本报告梳理全部功能、端到端逻辑链路，并单列「定义过但已无调用方」的冗余/遗留代码及其原本用途。

---

## 一、系统总览

「专注座」是一个自习室座位预约微信小程序，采用**前端（原生小程序）+ 微信云开发（云函数 + 云数据库）**架构。

### 1.1 前端结构
| 目录 | 职责 |
|---|---|
| `pages/` | 10 个页面（见 §3） |
| `components/` | 复用的 UI 组件（SeatMap 座位图、LoadingState/EmptyState 等） |
| `services/` | 业务服务层，封装云函数调用（`callCloud`） |
| `utils/` | 纯函数工具（时间、校验、订阅、座位命名、番茄钟等） |
| `store/` | 极薄的本地缓存（用户档案、进行中预约） |
| `config/` | 常量与订阅模板配置 |
| `types/` | TypeScript 类型定义 |

### 1.2 云函数清单（`cloudfunctions/`，共 18 个）
`login`、`categoryList`、`roomList`、`createReservation`、`cancelReservation`、`updateReservation`、
`checkin`、`leaveSeat`、`expireRecords`（定时触发器）、`studyRecord`（统一的学习/预约记录 CRUD）、
`studyRank`、`aiRecommend`、`aiSummary`、`notify`、`seedData`、`adminStats`、`adminOps`、
`shared/`（被复用的 `db`/`validator`/`aiClient`/`response` 公共模块）。

### 1.3 数据集合（云数据库）
- `users`：用户档案（`open_id_hash` 主键、`no_show_count` 违约次数、`banned_until` 禁约截止）。
- `records`：预约/学习/签到/暂离记录（`record_type` 区分；预约记录 `status` 见 §3.5 状态机）。
- `categories`：自习室（room）、座位属性（seat_feature）、学习目标（study_goal）、反馈标签（feedback_tag）；座位定义内嵌在 room 的 `metadata.seats` 里。
- 云存储：头像 fileID。

## 二、预约状态机（贯穿所有链路的基石）

预约记录在 `records` 集合中按 `status` 演进，前端 `config/constants.ts` 与多个云函数共用同一套取值：

```
pending_checkin（待签到）
   ├─> 开始 +15min 内签到成功 → active（使用中）
   │        ├─> 结束时间到 → completed（已完成）
   │        ├─> leaveSeat → paused（暂离中）→ returnSeat → active
   │        └─> 取消/提前结束 → cancelled
   └─> 超时未签到（>15min）/ 暂离超时（>30min）→ no_show（违约，座位释放 + 记违约次数）
```

**四类超时口径是系统最脆弱的一致性点**（见 §5）：`CHECKIN_TIMEOUT_MINUTES=15`、`LEAVE_TIMEOUT_MINUTES=30`、`MIN_BOOKING_MINUTES=15` 在 `config/constants.ts`、`cloudfunctions/expireRecords`、`createReservation`、`roomList`、`myReservations` 多处同步出现。

## 三、核心功能模块与逻辑链路

每个功能按「**前端入口 → 业务 service → 云函数 → 数据库 → 回调/副作用**」逐级打通。

### 3.1 登录与用户身份
- 入口：`pages/profile` 的「登录」按钮 → `services/auth.login()`。
- 链路：`profile.onLogin()` → `login()`（云函数）→ `cloudfunctions/login/index.js`。
- 云逻辑：取 `OPENID` → SHA256 哈希成 `userId`；校验管理员白名单（`ADMIN_OPENID_HASHES` 环境变量）；**惰性结算本人已超时预约**（`settleMyViolations`，不依赖定时器，避免「明明超时却没记违约」）；首次登录写 `users` 文档，否则更新昵称/头像。
- 缓存：`store/user.ts` 落本地，供全局读取。

### 3.2 自习室 / 座位浏览与实时占用
- 入口：Tab「自习室」`pages/rooms` → 选房 → `pages/seats`（座位平面图）。
- 链路：`seats.loadSeats()` → `services/room.listRooms()` → `roomList` 云函数。
- **三级降级（保证云端未部署也能点通 UI）**：
  1. `roomList` 云函数成功 → 含**实时占用**（座位随预约变红）→ `source='cloud'`；
  2. 失败但 `categories` 已初始化 → 只有房间/座位**定义**、无实时占用 → `source='static'`（页面强制提示「座位颜色不可信」）；
  3. 完全未初始化 → 本地 `DEMO_ROOMS`（3 房 26 座）兜底 → `source='demo'`。
- 占用口径：座位处于 `pending_checkin/active/paused` 且在时段内算占用；`releasedByTimeout`（15/30 分钟）之外的「超时但没翻状态」不占座——前端 `recomputeWindow()` 与 `roomList.isStale` 逐字对齐。
- 轮询：`seats` 每 15s 拉一次最新占用（`startPoll`），弥补无实时订阅。

### 3.3 选座与预约下单
- 入口：`seats.onSeatTap()`（空闲座位）→ 底部抽屉「立即预约」→ `onConfirmBooking()`。
- 链路：`requestReservationConfirmSubscribes()`（**先拉订阅授权，必须在手势内**）→ `createReservation()` → `cloudfunctions/createReservation/index.js`。
- 云逻辑：
  1. 入参白名单校验（`validateEvent`，F7 安全）；
  2. UGC 护栏：`goal` 过 `msgSecCheck` 内容安全；
  3. **开放时段「夹」**：`clampToOpenWindow` 把结束时间截断到打烊（能约多久算多久），而非整段拒绝；
  4. 违约拦截：读 `users.banned_until`，禁约期内拒绝；
  5. **事务内**做座位冲突 + 用户同时段冲突双重校验（并发互斥，杜绝双订）；`runTransaction` 的返回值是回调返回值本身（**不是 `{result}` 包装**，这是历史 bug 来源）；
  6. 落库 `status='pending_checkin'`，并把 `openid`/`room_name` 塞进 `payload`（供后端定时推送定位接收人）。
- 前端提示：若服务端截断结束时间 >1min，弹「已按开放时间调整」；非实时数据时弹「座位状态不是实时的」说明，避免「有空位却约不上」的困惑。
- 推送：成功后 `notifyReservationConfirmed()`（授权失败/未配置模板则静默跳过）。

### 3.4 订阅消息（授权 + 发送分离）
- **授权只能前端做**：`utils/subscribe.requestSubscribe()` → `wx.requestSubscribeMessage`，必须位于用户点击手势的**第一句**（任何前置 `await` 都会丢手势 → `can only be invoked by user TAP gesture`）。
- **发送只能云端做**：`cloudfunctions/notify`，是「模板 ID + 关键词编号 + 20 字截断」的**唯一数据源**；前端只传 `type`（4 种）+ 内容字段。
- 4 张模板（`config/subscribe.ts` 的 `SUBSCRIBE_TEMPLATES`，与 `notify` 的 `TEMPLATES` ID 必须一致）：
  ① 预约成功 `reservationConfirmed`；② 签到提醒 `checkinReminder`；③ 超时/违约预警 `reservationWarn`；④ 取消/违约通知 `reservationCancel`。
- 授权触发点：下单前（`seats`/`reservation`）、取消预约前（`myReservations`，但「结束使用」不申请）。
- 发送触发点：预约成功（前端）、取消成功（前端）、以及后端 `expireRecords` 定时推送。

### 3.5 签到
- 入口：`myReservations` 的「扫码签到」/`手动签到` → `checkinWithCode()` → `cloudfunctions/checkin/index.js`。
- 云逻辑：校验记录归属 + 状态必须为 `pending_checkin`；时间段校验（未到 / 已结束 / **超过 15min 宽限则拒绝**，避免「一椅两人」）；到店凭证三选一：
  - 签到码（`checkin_code`）：按 `房间+日期` HMAC 派生 4 位每日轮换码（`CHECKIN_REQUIRE_CODE` 开关可关，防远程签到）；
  - 座位码（`seat_code`）：扫码后必须与该预约座位一致（两侧 trim+大写归一化比对）；
  - 无凭证：受开关约束，否则要求输入签到码。
- 成功：`status → active`，写 `payload.checked_in_at`/`checkin_method`。

### 3.6 暂离 / 返回
- 入口：`myReservations` 使用中记录 → `onLeave()` → `leaveSeat(action:'leave')` → 云函数 `status → paused`；`returnSeat(action:'return') → active`。
- 暂离最长 30min，超时由 `expireRecords` 翻 `no_show` 并释放座位。

### 3.7 我的预约 / 取消 / 改约 / 违约倒计时
- 页面：`pages/myReservations`，Tab 分「全部 / 待签到 / 使用中 / 历史」。
- 取消：`onCancel` 先开**自绘弹层**（不用 `wx.showModal`，避免吃掉手势）→ `onConfirmCancel` 手势内先 `requestCancelSubscribes()`（仅未使用才申请）→ `doCancel()` 调 `cancelReservation` → 状态 `cancelled`/`completed`；取消（非结束）后 `notifyReservationCancelled()` 推 ④。
- 改约：`updateReservation` 云函数重写 start/end（服务端重校验冲突）。
- **前端违约倒计时**：`rowOf()` 实时计算 `releaseAt`（开始+15min / 暂离+30min），超时虽服务端还没翻 `no_show`，前端徽标先显示「已违约」，并移除失效的签到/返回按钮，与服务端口径一致。

### 3.8 超时违约与惩罚（双保险）
- **定时器路径**：`expireRecords`（云函数定时触发器，无用户态）→ 扫描超时的 `pending_checkin`/`paused`/`active`，批量翻 `no_show`/释放座位，发 ③ 预警，按梯度累加违约并刷新 `banned_until`（第1次30min / 第2次2h / 第3次起24h）。
- **惰性路径（兜底）**：`login.settleMyViolations`，每次登录顺手结算本人超时记录，幂等（用 `where({_id,status})` 条件更新，与定时器并发不重复计数）——解决「定时器没部署→违约不涨」问题。

### 3.9 AI 选座推荐
- 入口：`home` 弹窗（选偏好/时长）→ `recommendSeats()` → `cloudfunctions/aiRecommend/index.js`（`action:'recommend'`）。
- 链路：拉 `categories`（房间/座位特征/学习目标）→ 过滤维护中 + 当前被预约的座位 → 调大模型（超时重试 1 次）→ 解析 JSON 取前 3 候选；**任何失败都降级到 `fallbackRecommendations`**（按偏好匹配度打分），前端 `recommendation.source` 标记 `ai`/`fallback`。
- 结果卡：swiper 一次一张，点「前往预约」跳 `reservation` 页。

### 3.10 学习计划与番茄钟
- 入口：`home` 学习计划输入框 → AI 计划（`action:'generate_plan'`）或本地 `fallbackPlan`（按总时长拆 25min 段）；`study` 页（`tabBar`）运行番茄钟。
- 链路：`study` 页 → `services/record`（`startStudy/pauseStudy/resumeStudy/completeStudy/syncPomodoro` 等）→ `studyRecord` 云函数。
- 番茄轨迹：`utils/pomodoro` 计算专注/休息阶段；`syncPomodoro` 全量重推段轨迹（幂等），云端重算番茄数与休息扣减。
- 交接：学习页是 Tab 页，`switchTab` 不能带参，首页把「某一段计划」落本地缓存（`PENDING_STUDY_TASK_KEY`，10min 过期），学习页 `onShow` 取出自动开始。

### 3.11 学习记录统计与 AI 总结
- `fetchStudySummary`（`studyRecord` 的 `summary` 动作）→ 今日/累计专注秒数、番茄数、完成/放弃数。
- `fetchStudyAiSummary`（`aiSummary` 云函数）→ AI 生成学习总结与建议（未配置则降级）。

### 3.12 专注排行榜
- `pages/rank`（由 `profile.goRank` 进入）→ `fetchStudyRank` → `studyRank` 云函数，按时段（今日/本周/总榜）按专注时长排名，前端标记「我」。

### 3.13 管理后台
- `pages/admin`（仅管理员，`profile.goAdmin`）→ `services/admin`（`fetchAdminStats`/`setSeatMaintain`/`fetchRoomSeats`/`fetchCheckinCodes` 等）→ `adminStats`/`adminOps` 云函数。
- 功能：运营看板、座位维护态开关、签到码查看、用户信用管理（一键解禁/清零违约）。
- 数据初始化：`seedData` 云函数（由 `admin` 触发），`upsert` 写入 `categories`（**只增不删**，删旧条目需控制台手动删或 `resetCategories`）。

## 四、关键链路一致性风险（改动必须同步）

| 口径 | 涉及位置 | 风险 |
|---|---|---|
| 超时 15/30min、最短 15min | `config/constants.ts` + `expireRecords` + `createReservation` + `roomList` + `myReservations` + `seats`（前端 `durationMinutes`） | 任一处改了不报错，会出现「座位图全绿、点预约却报已被约」 |
| 订阅模板 ID | `config/subscribe.ts` 与 `notify` 云函数 `TEMPLATES` | 不一致 → 授权用 A、发送用 B，用户永远收不到 |
| 事务返回值 | 仅 `createReservation` | 误加 `{result}` 包装 → 记录已入库却报「预约失败」 |
| 开放时段「夹」 | `bookingWindow.ts` + `createReservation` + `updateReservation` | 三处实现必须同构 |
| 座位/属性命名 | 处处用 `window/power/outlet/quiet` | 删除某属性须同步种子 + 前端过滤（`single` 残留即典型教训） |

## 六、小结

- **功能链路是贯通的**：从选座→下单（事务冲突校验+开放时段截断）→签到（三凭证）→暂离/返回→超时违约（定时器+登录惰性双保险）→取消/改约，每一环都有明确的「前端 service → 云函数 → 库 → 回调」对应。
- **最大的脆弱点**是 5 处跨端/跨云的一致性问题（§4），已由常量、注释和 `cloud-logic.test.cjs` 断言守护。
- **可清理的冗余**集中在 `utils/validator.ts`（整文件）、`SeatCard/RoomCard/StatusBadge`（整组件）、一批未接管的导出函数与几处 SCSS 孤儿样式（§5）。这些不影响运行，但会增加维护噪音。
