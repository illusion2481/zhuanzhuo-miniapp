## P1-1 连续签到 streak（增长留存第一环）

### 云端 `cloudfunctions/checkin/index.js`
- 新增**纯函数** `nextStreak(prevStreak, lastCheckinDate, todayKey, yesterdayKey)`：
  - 北京时区日期键（`Asia/Shanghai` 格式化 `YYYY-MM-DD`），与系统既有日期口径一致；
  - `lastCheckinDate === yesterdayKey` → 连续，streak +1；
  - `lastCheckinDate === todayKey` → 当天已签，**不重置**（保持原值）；
  - 其他（断签/首次）→ 归 1。
- `recordDailyCheckin(userId, nowIso)`：`users` 文档写 `streak / last_checkin_date`，`total_checkin` 用 `_.inc(1)` 或初始化——**签到计数不依赖定时器**，天然与「违约靠 login 惰性结算」同一基调。
- 主流程在签到成功后调用，try/catch 包裹，失败不阻断签到本身。

### 前端
- `pages/profile/profile.ts/.wxml/.scss`：新增 **streak-card**（渐变卡）：连续天数大数字 + 「连续签到」标题 + 次行「累计签到 N 次」。
- `services/*`、`types/user.d.ts`：`UserProfile` 增 `streak / totalCheckin / lastCheckinDate`。

### 测试
- `scripts/cloud-logic.test.cjs` 增 4+ 断言：昨天连续 +1、当天重复不重置、断签归 1、首签 1；`recordDailyCheckin` 首次初始化 / 累加。

## P1.2 评价回流 AI（飞轮）

### 云端：新云函数 `submitReview`
| 项 | 内容 |
|---|---|
| SCHEMA | `record_id`(string, 必填) / `rating`(number 1-5, **clamp**) / `content`(string ≤200, optional) |
| 归属校验 | 记录必须 `completed` 且 `user_id === 本人` 且 `record_type==='reservation'` |
| 幂等 | `_id` = `rev_ + record_id`，先 `where({record_id})` 查重 → 已存在返回 `{already:true}`，不重复写 |
| UGC 审核 | 复用 `checkSafeText`（msgSecCheck），单条失败即拒绝提交 |

> 关键坑：**`_id` 前缀 + 编号法避免与 records 共用集合时的写覆盖**；测试里 mock store 全局共享，直接 `reviews.doc(record_id)` 会覆盖原预约记录。

### 回流：`aiRecommend`
- `listRoomsFromCategories` 聚合 `reviews`（limit 2000，异常→空数组不炸）→ 每座位 `rating / review_count`；
- `buildPrompt` 座位行追加「口碑 X 分（N 评）」；
- `fallbackRecommendations` 加分：≥3 评且 ≥4.5 → **+6**；≥1 评 → **+2**。AI 与兜底两路都吃口碑 →「评价飞轮」。

### 前端
- `pages/myReservations/*`：completed 卡片操作区出现「评价」；新 self-popup：五星点选（默认 5 星，`[1,2,3,4,5]`）+ 文本域 + 提交（去重防抖 `reviewSubmitting`）。
- `services/record.ts`：`submitReview({record_id, rating, content?})`。

## P1-3 分享裂变（指数级增长）

### 链路：分享 → 落地 → 绑定 → 奖励
```
home/profile 分享卡 ──inviter=<userId>──► 好友点开
   app.ts onLaunch: captureInviter() 暂存 storage(focusseat_inviter)
   首次 login：consumeInviter() 读取一次并清除 → 随 login 请求带 inviter
   login 云函数：非自邀 + 32位hex 校验 → users.invited_by 落库
   (好友)签到成功 → checkin: rewardInviterOnFirstCheckIn()
     条件更新 users.invite_rewarded=true（防重复）→ 邀请人 users.invite_credit _.inc(1)
```

### 关键防护
- **自邀拦截**：`inviter === 本人 userId` 不绑定；
- **格式校验**：`/^[a-f0-9]{32}$/i`（云函数侧，防注入脏数据）；
- **不覆盖**：storage 已有邀请人则不覆盖（先到先得，防洗量）；
- **幂等奖励**：`where({_id: user, invite_rewarded: _.exists(false)})` 条件更新，重复签到不二奖。

### 前端
- `utils/share.ts`：复活 `buildShareInvite / buildTimelineInvite`（`inviter` 拼 query）；`currentUserId()` 从 `store/user` 取（不涉及 token）。
- `app.ts`：`captureInviter()` 在 `onLaunch` 里、**cloud.init 前**调用（不依赖云端，断网也能暂存）。
- `services/auth.ts`：`consumeInviter()` 只读一次 + 删除（防重复上报），`login()` 带上。
- `pages/home` + `pages/profile`：`onShareAppMessage` 改走 `buildShareInvite`，补 `onShareTimeline`。

> 注：邀请积分（invite_credit）当前为**平台内虚拟分**，落地在 profile「邀请奖励 N 分」；真实商业化/钱包在 P2。
