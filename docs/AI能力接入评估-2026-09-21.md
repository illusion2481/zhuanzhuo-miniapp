## 1. 截图那个「微信 AI 能力」是什么

**它是让微信 AI 助手来操作你的小程序，不是给你一个可以调用的大模型。**

- 入口：小程序管理后台 → 基础功能 → AI 能力（2026-06-08 开放）
- **自动模式**：授权平台在提审时读取源码，平台自动分析页面结构并生成供 AI 调用的能力接口。**零开发**，适合中小团队。
- **开发模式**：自定义封装原子接口 / 原子组件 / Skill，经平台评测与审核后被微信 AI 调用。
- 两种模式**可同时开启、互不排斥**；开启不会影响现有小程序服务。
- 三个技术单元：原子接口（功能，如"选座位"）、原子组件（交互卡片）、Skill（整体使用手册）。
- 调用优先级：原子接口实际返回 > 主观声明 > Skill。关键字段（ID 等）必须来自接口真实返回，不允许 AI 生成；地址/手机号等必须脱敏。
- **当前处于内测阶段，用户暂时无法体验**——开了也暂时没有真实流量。

**能做**：未来用户对微信 AI 说"帮我预约明天下午的座位"，AI 直接调你的小程序完成。
**不能做**：给你 LLM 做总结、做推荐、做客服问答。

**建议**：**自动模式可以顺手开启**（零开发、零成本、不影响现有功能），作为"已接入微信 AI 生态"的占位；开发模式留待有精力时再评估。

当前通道：`https://chatapi.weixin.qq.com/openai/v1`（OpenAI 兼容协议）+ 环境变量 `CODING_PLAN_API_KEY` / `CODING_PLAN_BASE_URL` / `CODING_PLAN_MODEL`，模型默认 `Deepseek-v4-flash`。

已有的稳健设计（**保留**）：
- Key 只在云函数侧读取，不进前端、不进代码库
- 15s 超时 + 重试 1 次
- 三级降级：AI 成功 → AI 解析失败转本地兜底 → AI 未配置/异常转本地兜底，`source` 字段标记 `ai` / `fallback`
- 单次输入 ≤ 2000 字上限

**结论：这部分不用换成截图那个，也不用为了"接入 AI"再做什么。** 若要优化，只有"换通道"一个可选项（见 §4）。

## 3. AI 客服：两条路

### 路 A · 自建 AI 问答 + 转工单（推荐）

在 FAQ / 反馈页加「问 AI」入口；云函数把 FAQ（现有 11 条）+ 预约 / 签到 / 违约 / 取消规则作为知识库喂给模型；答不上来或用户点「转人工」时，**自动把对话摘要写进现有工单**（`records`，`record_type='feedback'`）。

优点：
- 复用现有三层客服架构，AI 定位为"第 1.5 层智能预筛"
- 用户问题进 `records` → 直接产出答辩要的**高频问题 TOP10 / 自助解决率**数据
- 不受微信客服 48 小时窗口限制
- 不需要动 mp 后台任何配置，不与人工客服冲突

代价：属于"AI 问答"，对外提供时同样受 §4 的深度合成类目约束。

### 路 B · 云开发 Agent 接管小程序客服会话

云开发 AI 控制台 → Agent → 接入指引 → 微信平台 → 小程序客服 → 授权（填入 AppId，管理员扫码）→ 云开发代理客服能力，AI 自动回复；需按「微信平台适配器」改造 Agent 消息格式。

优点：合规口径上，官方对个人主体**明确推荐**"用小程序客服消息等方式实现 AI 智能体"；用户无需离开聊天界面。

代价：
- 必须**关闭** mp 后台「功能 → 客服 → 在官方客服工作台收发消息」，否则机器人接管不了（与之前提的"别配消息推送"是同一类冲突）
- 接管后**人工就接不上了**（除非在适配器里自行转发给客服工具）
- 需单独维护 Agent 的提示词与知识库
- 仍受 48 小时回复窗口约束
- 建议提示词里约束输出长度、禁用 Markdown 以提升响应速度

### 对比

| | 路 A 自建问答 | 路 B Agent 接管客服 |
|---|---|---|
| 可留痕 / 可量化 | ✅ 全部进 `records` | ❌ 消息在微信侧 |
| 受 48h 限制 | 否 | 是 |
| 需改 mp 后台配置 | 否 | 是（且会挤掉人工） |
| 开发量 | 中（1 个云函数 + 1 个页面） | 中高（Agent + 适配器） |
| 与现有客服冲突 | 无 | 有 |

## 4. ⚠️ 上线合规：深度合成类目（最容易被卡的一关）

**只要小程序对外提供 AI 问答 / AI 生成内容，微信要求申请「深度合成」服务类目；缺类目提审 100% 驳回。**

- 子类目：深度合成 > AI 问答 / AI 绘画 / AI 换脸 / AI 创作
- **仅非个人主体可申请**（企业 / 组织 / 个体工商户），个人主体无法开通
- 资质二选一：
  - **自研技术**：小程序主体的《互联网信息服务算法备案》（生成合成类），备案主体须与小程序主体完全一致，周期 2–4 个月
  - **第三方技术**：技术方的算法备案 + 双方盖章合作协议（写明算法名称/备案编号/应用场景）
- **云开发场景属于"使用第三方技术"，可由平台直接出材料**：
  1. 前提：小程序通过**企业认证** + 云开发环境有效期 **≥ 3 个月**
  2. 云开发控制台 → AI → 「获取算法合作协议」→ 填入 AppId 与主体名称
  3. 平台生成：① 腾讯云《互联网信息服务算法备案》截图 ②《深度合成算法合作协议》
  4. mp 后台 → 设置 → 基本设置 → 服务类目 → 添加「深度合成 > AI 问答」→ 选**资质 2.2** → 上传上述两份材料
  5. 类目审核 1~2 个工作日（最多 7 个）；**类目必须先过，再提交代码**
- **个人主体的替代路径**（官方建议）：用 H5、公众号，或**小程序的客服消息**等方式承载 AI 功能 → 这也是 §3 路 B 值得优先考虑的原因

**三个高频驳回点**（都不是大改动，但漏一个就被打回）：
1. 界面没有**显著**标注「AI 生成」——要求全程固定展示，不能角落小字、不能只弹一次
2. 用户协议 / 隐私政策缺 **AI 免责条款**（说明内容由 AI 生成、不可用于医疗/法律/金融决策）
3. **未接入内容安全过滤**——用户输入与 AI 输出都要过 `security.msgSecCheck`

## 5. 成本

**通道一：云开发 AI+（推荐）**
- 小程序端：`wx.cloud.extend.AI`，需基础库 **3.15.1+**（本项目 `libVersion: 3.17.2` ✅）
- 可用模型：`hy3-preview`（体验）、`deepseek-v4-flash` / `deepseek-v4-pro`、`glm-5.1`、`kimi-k2.6`、`minimax-m2.7` 等
- 云函数侧可用 Node SDK 或 OpenAI 兼容协议
- 优势：Key 由平台托管不暴露、走内部通道免配域名白名单、原生支持流式、**可借腾讯云的算法备案资质**（§4 的关键）

**费用**
- Token 资源包：**1000 Token 点 = ¥1**，有效期 1 年，独立计费不占套餐额度
  - 5 万点 ¥50（跑通 demo）｜10 万点 ¥100（个人项目冷启动）｜100 万点 ¥1000（正式上线）
- **小程序成长计划**：微信公众平台 → 行业能力 → 小程序成长计划报名
  - 已有云开发环境 → 领 **120 元代金券 + AI 资源包**（额度已从 1 亿提升至 **10 亿 Token**，另含生图额度），**6 个月有效**
  - 未开通环境 → 免费 6 个月个人版环境
  - 注意：成长计划资源包**限微信小程序与云开发控制台内调用**
- 体验模型（混元）免费，但单环境并发上限 5，不适合正式流量

## 6. 建议优先级

1. **先确认小程序主体身份**（个人 / 企业 / 个体工商户）——它直接决定 AI 功能能否通过审核，是根问题，优先于任何开发
2. **报名小程序成长计划**（如果还没报）——拿免费额度，零成本
3. **若主体非个人**：把 AI 通道切到云开发，并在提审前完成深度合成类目申请（材料可由云开发平台生成）
4. **若主体是个人**：AI 功能不要暴露在小程序页面里；改走**客服消息**承载（§3 路 B），或暂不上线 AI 相关界面
5. AI 客服先做**路 A**（自建问答 + 转工单）验证需求，再决定是否做路 B
6. 顺手开启「AI 能力 → 自动模式」（零成本占位）
