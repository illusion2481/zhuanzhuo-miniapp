> 审计日期：2026-09-22 ｜ 审计方式：代码静态追溯（前端服务层 ↔ 云函数 ↔ 页面入口 ↔ 数据读写闭环）

## 一、结论总览

本系统**核心业务闭环整体完整**：预约 → 签到 → 学习 → 评价 → 排行榜 → 管理后台 → 订阅消息，均已串通并被
`scripts/full-audit.cjs`（链路级自检）与 `scripts/cloud-logic.test.cjs`（395 项单测）守护。

但审计发现 **6 条断链 / 半环**（2 条 P1、4 条 P2），均为「写了但没人看 / 做了但没入口」类问题，
不影响主流程运转，但会造成功能空转或用户困惑。

## 二、断链清单

### 🔴 P1-1　`bindPhone` 云函数「零前端调用」—— 手机号绑定功能不存在

| 项 | 内容 |
|---|---|
| 写侧 | `cloudfunctions/bindPhone/index.js`（完整实现：getPhoneNumber code 换号、写 `users.phone`、脱敏返回） |
| 读侧 | `miniprogram/types/user.d.ts:33` 声明了 `phone?: string`；`login/index.js:159` 的 `toProfile()` 已透出 `phone` |
| 断点 | **全项目无任何 `.ts` / `.wxml` 引用 `bindPhone` 或 `getPhoneNumber` 或按手机号展示**（唯一 hit 是按钮组件类型声明） |
| 影响 | 云函数已部署、字段已在透出，但用户没有任何入口绑定手机号 → 「绑定手机号」功能实际不存在 |
| 修复建议 | ① 在「我的」页加「绑定手机号」入口（`button open-type=getPhoneNumber` → `callCloud('bindPhone',{code})` → `login()` 刷新），且 `bindPhone` 需配环境变量 `WX_APP_SECRET`；② 或明确下线该云函数与字段，避免「半成品」悬挂 |

## 四、潜在隐患（不构成断链，但需留意）

1. **`aiChat` / `faq` 双 FAQ 数据源** —— `subpages/faq/faq.ts` 与 `cloudfunctions/aiChat/index.js` 的 `FAQ_ITEMS` 同构但为 **两份独立数据**，依赖「手动同步」，改一处漏一处会造成 AI 与页面答案不一致。建议后续收敛为单一 JSON 源生成。
2. **`TAB_PAGES` 常量未含 `pages/admin/admin`** —— 但该常量仅供首页 `switchTab` 跳转（`home.ts:518`），admin 已是 tabBar 第 5 项，非缺陷（只读备注）。
3. **签到榜（`RankBoard = 'checkin'`）与 `checkin` 云函数同名** —— 语义不同（签到次数榜 vs 签到动作），阅读时注意区分，非缺陷。

## 五、结语

核心体验闭环完整，**真正值得动手的是 P1-1（手机号绑定无入口）与 P1-2（邀请积分无展示）**：
两者都是「云端功能写好了、前端没接上」，成本低、对用户价值清晰（前者合规能力、后者裂变闭环）。
P2 项属体验优化与文案一致性，建议随下一版本顺手修。
