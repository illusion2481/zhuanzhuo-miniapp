## 1. ⚠️ ICP 备案（主指南漏了，最硬的硬门槛）

**2024 年起，微信小程序强制要求 ICP 备案，未备案无法上线**（个人主体同样要备案，免费；企业收费见主体类型）。

- **入口**：mp 后台 → 设置 → 小程序备案 → 去备案
- **个人主体**：身份证 + 手写签名按手印，地址要**详细到门牌号**
- **流程**：提交 → 监管审核 → 工信部 12381 发核验短信 → 点链接完成核验 → 拿到备案号
- **节奏**：备案通常 1~2 周，**和提审并行办理**，别等提审时才想起
- **对你**：`appid: wxfc0e04dee08cc17d`，参赛通道要求「正式上线」，备案是第一步，**务必最早启动**

## 2. ✅ 无需配置 request/uploadFile 合法域名（好消息，可整段跳过）

我全量 grep 了 `miniprogram/`，**没有任何 `wx.request()`**（所有 HTTP 都走云函数）。加上没有 `wx.uploadFile`，所以：

- **不需要**在 mp 后台「服务器域名」里配任何域名
- 需要做的就是：**云开发环境开通 + 云函数部署**，前端只走 `wx.cloud.callFunction`

> 这是云开发项目的天然优势：审核时「服务器域名」整栏可以空白。

## 3. ⚠️ 上传前必须「构建 npm」（否则 tdesign 组件全部失效）

- 代码依赖 **TDesign**（`miniprogram_npm/` = `tdesign-miniprogram`），这个目录是**构建产物**，目录本身没有 `package.json` 时需要的 npm 构建产物在「npm 构建」后生成。
- **操作**：微信开发者工具 → 工具栏「工具」→「构建 npm」→ 生成 `miniprogram/miniprogram_npm/`（包含 `tdesign-miniprogram`、`tslib`）
- **不构建直接上传** → 自定义组件引用失败、页面白屏/报错「Component is not found」
- 确认产物存在：`miniprogram/miniprogram_npm/tdesign-miniprogram` 目录应在（当前已确认 ✅ 存在）
- 上传时确认**已构建且是最终版**：改完依赖/组件后要**重新构建 npm 再上传**

## 4. ⚠️ 所有密钥必须走云函数环境变量，前端永远不写死

- 你代码里唯一的 key 是 `CODING_PLAN_API_KEY`——**只出现在 3 个 AI 云函数的环境变量里**，前端**没有任何 key**（`wx.cloud.callFunction` 无 key,审核不会查）。
- 规则：**任何 token/key/secret 禁止出现在 `miniprogram/` 任何文件里**，只放云函数环境变量。
- 已在 `project.config.json` 的 `packOptions.ignore` 里排除了 `.env`/`.env.local`/`**/*.map`，但**每次改配置后重传前自查**：用开发者工具「上传」界面顺带看有没有泄露（通用做法：git 排除 + 上传排除）。

## 5. ⚠️ 订阅消息模板 ID 是真实值，但必须逐张核验

代码里 `reset` 已写死 4 张模板 ID（`miniprogram/subpages/config/subscribe.ts` + `cloudfunctions/notify/index.js`），**但 ID 是否生效取决于**：

- mp 后台 → 功能 → **订阅消息** → 我的模板，**4 张模板必须 ALL 已选用**（否则授权时该 ID 无效 → `requestSubscribeMessage` 报「模板不存在/TAP 失败」）
- **关键词字段名必须逐字一致**：`reset` 保存了 2026-09-22 实际抄录的 `{{thing9.DATA}}/{{time2.DATA}}` 等。若你换模板重新选了关键词，编号会变 → 发送报 47003「data.thingN.value is empty」→ 记得同步改 `subscribe.ts` + `notify/index.js` 两处
- 未配置订阅消息**不至于阻塞上线**，但预约成功/签到提醒/违约预警全收不到用户会困惑——上线版本建议：4 张模板**全部选好并加进代码**（当前已就绪）

## 6. ⚠️ 定时触发器别名配置的易错点

- `expireRecords` 的定时触发器必须**配了才跑**，漏配 = 违约/封禁永不产生（主指南 ⑤ 已写）
- 补充易错点：cron 是**七段**（秒/分/时/日/月/周/年），填错段数会在触发器保存时报错或静默不跑
- 建议先配 `0 */5 * * * * *` 测试 5 分钟一跑，日志确认后在改回 `0 0 3 * * * *`

## 7. ⚠️ 提审版的全量空状态检查（评审直接体验的环节）

评委/审核员只看到正式版，而且是**全新环境**——最容易翻车的点：

| 空状态 | 必须确认 |
|---|---|
| 选座页「当前无预约/无座位」 | 能正常展示空状态，不白屏 |
| 记录页「暂无学习记录」 | 空态文案 + 引导可用 |
| 后台页「无数据」 | tab 渲染不崩，展示空列表 |
| 积分卡「0 积分」 | 按钮置灰，不报错 |
| AI 客服「未配 Key」 | 降级文案友好（不能报错） |

建议：**正式版提交前，用一个全新微信号登录跑一遍**「首次进入 → 完善资料 → 空列表状态 → 预约一个 → 完整闭环」，确认任何空都存在兜底展示。

## 8. ✅ `IS_DEV` 一处即可，后台 tab 已按角色隔离（实查确认）

`miniprogram/config/env.ts` 第 8 行 `IS_DEV = true` → 改 `false`。作用已被实查确认：

- `pages/admin/admin.ts:136`：`showDevTools: IS_DEV` —— 只控制后台页内「数据初始化工具」按钮的显隐
- `custom-tab-bar/index.js:95`：**「后台」tab 本身按角色过滤**（`TAB_LIST.slice(0, ADMIN_INDEX)`）——非管理员根本看不到后台 tab，与 `IS_DEV` 无关
- 结论：发布版只要 `IS_DEV=false` + 管理员白名单配好（`ADMIN_OPENID_HASHES`），后台入口自然只对管理员可见，无需其他改动

## 9. 提审资料的「图片」坑

- 小程序头图 logo、二维码、截图**必须是 jpg/png**，且满足：头像 ≤2MB、144×144 推荐尺寸
- 提审时「功能页面」自动抓取**并不是全部页面**——会抓首屏 + 底部 tab，**审核员只用录屏 + 截图体验**，空状态体验差 = 直接被拒风险

## 10. ⚠️ 赛前冻结 vs 提交审核管理

**关键纪律：一旦提交审核，就不能随便再动代码**（审核是快照）。建议：

1. 提审前一天做**最终冻结**：跑全量验证（tsc/eslint/tests，409+77）
2. 把**最终可运行版本**打存在 `_backup` 或 git tag
3. 提审期间不再改任何功能，只允许紧急 bugfix
4. **提审通过后如果改代码**：必须重新上传新版本，且每次改动都要过上面所有验证
