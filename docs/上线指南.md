### ② 云函数部署（22 个）

**统一操作**：微信开发者工具 → 左侧资源管理器展开 `cloudfunctions` → 右键**函数文件夹** → **「上传并部署：云端安装依赖」**。

> ⚠️ 上传方式说明（纠正一个常见误区）：
> - 本项目**每个函数目录都自带 `shared/` 子目录**（如 `./shared/aiClient`、`shared/presence.js`），通过相对 `require('./shared/...')` 引用。
> - 无论选「云端安装依赖」还是「所有文件」，**`shared/` 都会随源码一起上传**——它不是 npm 依赖，不依赖云端安装。
> - 因此 22 个函数**统一用「云端安装依赖」即可**，无需逐个选「所有文件」。（「所有文件」会把本地 `node_modules` 也传上去，更慢且没必要，因为函数目录里已有 `package.json` 让云端装 `wx-server-sdk`。）
> - 部署顺序：**`login` 最先**（创建 `users` 集合与用户档案），其余顺序不限。

### ③ 环境变量配置（云开发控制台 → 云函数 → 选中函数 → 配置 → 环境变量）

> ⚠️ 微信云开发**没有全局环境变量**，必须**按函数逐个配置**，漏一个该函数就失效。

| 函数 | 变量名 | 值 | 必配 |
|---|---|---|---|
| `aiChat` | `CODING_PLAN_API_KEY` | 大赛提供的 Token | ✅ 必配 |
| `aiRecommend` | `CODING_PLAN_API_KEY` | 同上 | ✅ 必配 |

| `adminOps` | `ADMIN_OPENID_HASHES` | 管理员 `open_id_hash`（sha256(openid) 前 32 位，多人逗号分隔） | ✅ 必配（后台操作鉴权） |
| `adminSeatMaintain` | `ADMIN_OPENID_HASHES` | 同上 | ✅ 必配 |
| `login` | `ADMIN_OPENID_HASHES` | 同上（用于前端判断是否显示管理员身份） | ✅ 建议配 |

### ④ 数据库集合、权限、索引

**建集合**（云开发控制台 → 数据库 → 新建集合）：`users`、`records`、`categories`、`reviews`、`audit_logs`。
> `reviews` **必须建**，否则评价提交直接失败（云开发不会自动建集合）。

**权限**（云函数调用不受权限限制，可放心收紧；以下为前端直连场景下的安全设置）：

| 集合 | 权限建议 |
|---|---|
| `categories` | 所有用户可读、仅管理端可写（选座页 `watch()` 依赖读权限） |
| `reviews` | 仅管理端可读写 |
| `records` | 仅管理端可读写 |
| `users` | 仅管理端可读写 |
| `audit_logs` | 仅管理端可读写 |

**索引**（提升查询性能，控制台 → 集合 → 索引管理）：
- `records`：`record_type` + `created_at`
- `users`：`open_id_hash` 唯一
- `categories`：`type` + `code` 唯一
- `reviews`：`record_id`

### ⑤ 定时触发器（必做，否则超时违约不计）

`expireRecords` 负责把超时未签到的预约标记为违约。不配触发器它就**静默不跑**，违约/封禁都不会生效。

操作：云开发控制台 → 云函数 → `expireRecords` → **触发器** → 新建定时触发：
- 生产建议：`0 0 3 * * * *`（每天凌晨 3 点）
- 开发验证期可先用 `0 */10 * * * * *`（每 10 分钟）观察一次再改回

## 第二部分：正式上线步骤

### Step 1 上传小程序 → 体验版

1. 微信开发者工具右上角点 **「上传」**。
2. 填：版本号（如 `1.0.0`）、项目备注（如「初版：预约+签到+积分+AI」）。
3. 确定 → 打包上传（1~2 分钟），成功后弹**体验版二维码**。
4. 体验成员：mp 后台 → 成员管理 → 添加**体验成员**微信号，他们才能扫码。

### Step 2 真机全链路自测（体验版）

用自己手机 + 体验成员手机各跑一遍：
- [ ] 首次进入 → 完善资料引导（头像+昵称）→ 回首页
- [ ] 选座 → 预约 → 签到（围栏+签到码）→ 签退
- [ ] 邀请好友 → 好友首次签到 → **双方积分各 +1**
- [ ] 「我的」页积分卡 → 抵免违约（积分 -1、违约 -1、已抵免 +1，上限 10）
- [ ] AI 客服 / 推荐 / 总结 能正常返回（非降级文案）
- [ ] 后台管理（管理员）入口可见、操作可用

### Step 3 提交审核

mp 后台 → 管理 → **版本管理** → 开发版本 → **提交审核**：
- 功能页面：系统自动抓取，确认含 `pages/home`、`pages/profile` 等核心页。
- 类目：按业务选（如「教育-在线教育」或「工具」）。
- 测试说明：写清审核员用什么入口、看什么功能。
- 审核周期：个人主体约 2~7 个工作日。

### Step 4 过审 → 发布（即「正式上线」）

审核通过 → 版本管理 → 该版本出现 **「发布」** 按钮 → 点击 → 正式上线，所有人微信可搜到。
**这一步必须在 2026-10-17 前完成，否则不满足大赛参赛资格。**

### Step 5 上线后监控

- 云开发控制台 → 云函数日志：确认无 `AI_NOT_CONFIGURED`、`AI_NO_FETCH`、`UNKNOWN_ACTION` 报错。
- 观察 `expireRecords` 触发器是否按时执行（违约/封禁是否正常产生）。
- 关注用户体验反馈（大赛评审维度含「正式上线后用户反馈数据」）。

## 第四部分：常见问题 / 排错

| 现象 | 根因 | 解决 |
|---|---|---|
| 「我的」页点「抵免违约 -1」报错 / 无响应 | `useCredit` 未部署 | 部署 `useCredit`（云端安装依赖） |
| AI 客服/推荐报「走神了」「暂时走神」 | `CODING_PLAN_API_KEY` 漏配（三个 AI 函数各自配） | 逐个函数配 Token |
| AI 报 `AI_NO_FETCH` | 云端 Node 版本无全局 fetch 且兜底失败 | 确认 `shared/aiClient.js` 随函数上传（云端安装依赖即可） |
| 真机换头像/签到定位失败，模拟器正常 | 未申请位置接口 / 隐私指引未发布 | 接口设置申请 + 发布隐私指引 |
| 评价提交失败 | `reviews` 集合未建 | 控制台新建 `reviews` |
| 违约/封禁一直不产生 | `expireRecords` 没配定时触发器 | 配 cron `0 0 3 * * * *` |
| 后台管理入口不显示 | `ADMIN_OPENID_HASHES` 未配或 hash 不对 | 用真实 `open_id_hash` 填白名单 |
| 审核驳回：隐私相关 | 《用户隐私保护指引》未发布或漏勾选项 | 发布并勾选头像/昵称/位置 |
| 代码改动线上不生效 | 改完没重新编译 / 没重新上传 | 开发者工具编译 → 上传新版本 |
