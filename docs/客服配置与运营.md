# 客服配置与运营（手工操作清单）

> 本文件记录**只能在微信公众平台（mp）后台完成**的客服配置。
> 代码侧已做完「三层客服」：**AI 客服（`aiChat` 云函数，24h 秒回）→ 意见反馈工单 → 人工兜底**。
> 前两层零人工、随时可用；只有「人工」这一层要在网页后台绑定客服人员才会有人回（可选）。

---

## 0. 先分清产品形态，别配错

| | **AI 客服（本项目自带）** | **小程序客服消息** | **微信客服**（企业微信客服） |
|---|---|---|---|
| 前端调用 | 项目内聊天页 `/pages/aiChat/aiChat` | `<button open-type="contact">` | `wx.openCustomerServiceChat({ corpId, extInfo })` |
| 主体要求 | 无限制 | 个人 / 企业主体**都能用** | **仅非个人主体**，还需企业微信企业 ID |
| 谁来回 | **DeepSeek 大模型**（FAQ 知识库驱动，24h 秒回） | 绑定的客服人员**个人微信** | 企业微信里的客服账号 |
| 是否接入本项目 | ✅ 已上线（需配 `CODING_PLAN_API_KEY`） | ✅ 保留为人工兜底 | ❌ 个人主体小程序开不了 |

个人主体的小程序（学生比赛常见）**接不了真「微信客服」**。「人工」那一层用小程序客服消息（需绑客服，
见下）；**「AI 客服 + FAQ + 工单」不依赖你在线、始终有人回** —— 这才是个人项目该有的客服形态。

---

## 1. AI 客服（代码已就绪，只需配置环境变量）

「我的 → 联系客服」现在**默认进入 AI 客服聊天页**（`aiChat` 云函数）：
FAQ 知识库 12 条 + DeepSeek 大模型智能回答；命中「退款 / 投诉 / 人工」等关键词直接转人工，
答不上引导提交工单。

**要做的（一次性）：**
1. 部署 `aiChat` 云函数（含 `shared/` 目录，右键「上传并部署：所有文件」）
2. 给 `aiChat` 配环境变量 `CODING_PLAN_API_KEY`（与 `aiRecommend` / `aiSummary` 同一个 Key，
   即大赛 Token；不配则 AI 不可用，聊天页会提示稍后再试）
3. FAQ 知识库在 `cloudfunctions/aiChat/index.js` 的 `FAQ_ITEMS` 数组里，想改文案/加问题改那里，
   改后重新部署

> 这是个人主体项目"无人值守也有人回"的**唯一可行解**（真·微信客服接不了，真人又只有你一个）。

---

## 2. （可选）绑定人工客服兜底（一次性，约 2 分钟）

> AI 客服答不上时，聊天页可一键「转人工客服」（`open-type=contact`）。
> 要让这条通道**真的有人回**，必须在 mp 后台绑定客服人员：

1. 打开 **https://mp.weixin.qq.com/** 登录小程序
2. 左侧菜单：**功能 → 客服**
3. 点 **「添加」**
4. 填写客服人员的**微信号**（⚠️ **不是手机号，也不是昵称**）
5. 被添加人会收到邀请，需本人**扫码确认**后才生效

绑定名额限制：
- 一个**微信号最多被绑为 5 个**小程序 / 公众号的客服
- 一个**小程序最多 100 个**客服人员

**不绑会怎样**：AI 客服照常工作（FAQ + 智能应答不受影响）；只是点「转人工」后进的原生客服会话
没人回（表现同之前：消息"已送达"但无回复）。

---

## 3. 绑定后：在哪里回复用户

二选一：

| 方式 | 入口 | 适合 |
|---|---|---|
| **客服小助手小程序**（推荐） | 微信里搜「**客服小助手**」 | 手机随手回，能收推送 |
| 网页版 | **https://mpkf.weixin.qq.com/** | 电脑上处理，扫码选账号 |

> ⚠️ 用「客服小助手」时必须把客服状态设为「**在线**」，否则收不到新消息提醒。

---

## 3. 验证：确认真的通了

用**另一个微信号**进小程序 →「我的 → 联系客服」→ 发一条消息，然后看：

- [ ] 「客服小助手」小程序**弹出了新消息提醒**
- [ ] 回复一句，用户端**能收到**
- [ ] 客服侧能看到「**用户 ID + 来源页**」的上下文（本项目 `session-from` 透传的，
      形如 `{"uid":"5c38f3d7…","p":"profile"}`）——看到就说明透传生效了

**没绑客服人员时的表现**：用户发消息显示「已送达」但永远没人回。
这不是 bug，是消息进去了没人接。

---

## 4. 五条必知的坑

| 坑 | 说明 |
|---|---|
| **48 小时窗口** | 自用户**最后一条消息**起 48 小时内才能回复，超时连回都回不了 |
| **别配「消息推送」** | 一旦在 mp 后台配置消息推送，客服消息会**改推到你自己的服务器**，客服小助手 / 网页版就**再也收不到**了。本项目**不要配** |
| 聊天记录留存 | 微信侧云端留存 **30 天**，超期不可回溯 |
| **不落我们的库** | 客服会话内容只存在微信侧，**后台「反馈」Tab 看不到**。要留痕必须走「意见反馈」 |
| 会话抬头 | 微信里显示的是**小程序名称**（本项目「随处办」）。若显示的不是你的小程序名，说明点进了别家的客服 |

## 5. 本项目的客服分层（代码侧已实现）

客服不是一个按钮，是三层分流；**「AI 客服」现在把第 1 层升级为 24h 智能应答**：

```
第 0 层 AI 客服（新增 ★ 个人主体无人值守的唯一正解）
  pages/aiChat AI 客服聊天页 → aiChat 云函数（FAQ 知识库 12 条 + DeepSeek）
  入口：「我的 → 联系客服」默认进这里；faq 页「找 AI 客服」同样可进
  命中退款/投诉/人工等关键词 → need_human → 页内给「转人工客服 / 提交工单」出口
  需要配置：CODING_PLAN_API_KEY（同 aiRecommend，大赛 Token）

第 1 层 自助（零成本）
  pages/faq 常见问题（8+3 条，含签到失败专项）
  入口：「我的 → 常见问题」；以及签到失败页内联「签不上？查看常见原因」

第 2 层 工单（异步、留痕、可量化）★ 主力
  pages/feedback 意见反馈 → submitFeedback 云函数 → records 集合
  状态机：pending 待处理 → replied 已回复（等用户确认）→ handled 已关闭
  用户可「继续追问」（工单重开回 pending），可「问题已解决」（关闭）
  后台：小程序「后台 → 反馈」查看和回复
     · 工单显示「提交者昵称 · 短 ID」，管理员认得出是谁
     · 后台 Tab 角标显示待处理数（超 24h 未响应转红色），不必切进去才知道有新工单
     · 卡片显示「已等待 X 小时」，超时标注「已超时」（SLA 24 小时）
     · 用户追问会重置计时，不会把刚催过的单子误判成超时

第 3 层 人工（即时、只能处理复杂问题）
  open-type="contact" 原生客服会话 ← 本文第 1~2 节配置的就是这层
  AI 客服页内「转人工客服」一键直达；透传用户 ID 哈希（session-from）
  升级路径：AI 答不上 → 转人工 / 提工单
```

**运营建议**：把主要精力放在第 2 层。第 3 层即使配好了人，
也有 48 小时窗口、不落库、需要有人盯这三个硬伤；第 2 层能给出
「收到 N 条 / 已回复 N 条 / 平均响应时长 / 高频问题 TOP10」这类**答辩能用的数据**；
第 1 层（AI 客服）则保证你离线时用户也"有人回"。
