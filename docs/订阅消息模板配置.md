## 二、哪些功能需要订阅消息？

订阅消息只适合**「用户动作触发 / 定时触发的服务结果通知」**。**以下功能的推送才有意义**：

| # | 可推送功能 | 触发时机 | 对应模板 |
|---|---|---|---|
| 1 | 预约成功确认 | 预约创建成功 | 预约成功通知 |
| 2 | 到点签到提醒 | 预约开始前 X 分钟 | 签到提醒 |
| 3 | 待签到超时预警 | 距开始 ≥15min 仍未签到前提醒 | 预约提醒通知 |
| 4 | 暂离超时提醒 | 暂离接近 30min 上限时提醒返回 | 预约提醒通知（复用） |
| 5 | 爽约 / 违规禁约通知 | 记 `no_show` 或触发禁约时告知 | 预约取消通知 |
| 6 | 预约取消 / 改期通知 | 用户或管理员取消预约 | 预约取消通知（复用） |

其余功能（登录、浏览、筛选、番茄钟、统计、AI、排行榜、管理端、分享、日志、更新等）**都是应用内交互或行为记录，不需要、也不应该发订阅消息**（微信会判定为营销骚扰）。

## 四、在公众平台的具体操作步骤

### 第 1 步：补服务类目（若搜不到模板）
设置 → 基本设置 → 服务类目 → 添加 **生活服务 > 休闲娱乐（或其他）**，否则公共模板库可能不显示预约类模板。

### 第 2 步：逐张选用模板（✅ 已完成）
进入 **功能 → 订阅消息 → 我的模板 → 选用（公共模板库）**，分别搜索并选用下面 4 张：

1. 搜「**预约成功**」→ 选「**预约成功通知**」→ 勾选 `预约门店 / 预约时间 / 温馨提示`
   （⚠️ 该模板关键词池**没有「预约项目」**，第一格必须用「预约门店」承载自习室名）
2. 搜「**签到提醒**」→ 选「**签到提醒**」→ 勾选 `签到地点 / 签到时间 / 温馨提示`
3. 搜「**预约提醒**」→ 选「**客户预约提醒**」→ 勾选 `预约人 / 预约时间 / 预约事项…`
4. 搜「**预约取消**」→ 选「**预约取消通知**」→ 勾选 `预约项目 / 预约时间 / 温馨提示`

每张提交后，在「我的模板」点开详情，**核对 `{{thing1.DATA}}` / `{{time2.DATA}}` … 的编号顺序**，与第三节矩阵一致即可。
若实际编号与默认不同（例如时间是 `date2` 而非 `time2`），**只改 `config/subscribe.ts` 的 `SUBSCRIBE_KEYS` 一行**，无需动业务代码。
（①②④ 已核对为 `thing1/time2/thing3`，无需改动；③ 待启用时再核对。）

## 五、代码现状与待办

| 功能 | 代码状态 | 还差什么 |
|---|---|---|
| ① 预约成功确认 | ✅ 完成 | **已可发**（4 个模板 ID 已填，上传 `notify` 云函数即生效） |
| ② 签到提醒 | ✅ 完成 | 复用 `expireRecords` 的 5 分钟定时器扫描即将开始的待签到预约，发 `checkinReminder` |
| ③ 超时预警 / 暂离提醒 | ✅ 完成 | `expireRecords` 把 `pending`/`paused` 判为 `no_show` 时，经 `notify` 发 `reservationWarn` |
| ④ 取消 / 爽约 / 违规 | ✅ 完成（用户取消路径） | `cancelReservation` 在用户主动取消时经 `notify` 发 `reservationCancel` |

> ⚠️ **一次性订阅的授权收集时机**是这套机制的关键：
> 一张模板「授权一次只能推一条」。预约时一次性收集 3 个模板授权（微信单次上限）：
> - `reservationConfirmed`：当场消费（预约成功确认）
> - `checkinReminder`：额度留给「到点签到提醒」定时器
> - `reservationWarn`：额度留给后端「超时/违约预警」（用户无动作，只能提前收集）
>
> ④ 的 `reservationCancel` 则在**用户点击取消**这个主动动作里单独授权一次，当场消费。
> 因此 4 张模板全部覆盖，且每次授权的模板数 ≤3（微信限制）。
>
> 触发链路一览：
> - ① 客户端 `notifyReservationConfirmed` → `notify.send(reservationConfirmed)`
> - ② `expireRecords` 定时器 → `notify.send(checkinReminder)`
> - ③ `expireRecords` 定时器（no_show）→ `notify.send(reservationWarn)`
> - ④ `cancelReservation` 云函数 → `notify.send(reservationCancel)`
>
> **所有后端推送都依赖 `record.payload.openid`**（创建预约时由 `createReservation` 落库），
> 这是定时器无用户态时定位接收人的唯一依据；若历史数据缺该字段，对应推送会被静默跳过（不影响主流程）。

## 六、合规与频控提醒

- **一次性订阅**：用户授权一次 = 只能下发一条该模板的通知，**用完即失效，需再次授权**；
  自习室类目通常不支持长期订阅。因此「授权收集时机」必须提前设计（见第五节）。
- **不要营销化**：订阅消息只能发「服务结果通知」，不能发活动促销，否则会被微信封禁。
- **字段格式**：`time` 类型须为 24 小时制（可带年月日），本项目统一发 `2026年9月16日 15:00`；
  `thing` 最多 20 字；超长/空值会报 `47003`，`notify.ts` 已做 `clamp(20)` 截断兜底，但建议源头控制好。
- **先验证再群发**：先用测试号在真机点一次预约，确认收到卡片、字段正确，再全量。
